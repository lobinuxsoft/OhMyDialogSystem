Dialogue Nodes

OhMyDialogSystem utiliza un sistema de nodos visuales para construir grafos de dialogo. A diferencia de otras herramientas, nuestro sistema es hibrido: combina estructura de grafos con generacion dinamica por IA.

Diferenciador clave: La IA genera el CONTENIDO, el grafo controla la ESTRUCTURA. Haz click en cualquier nodo para ver sus parametros detallados.

Modos de Operacion

El DialogueManager puede operar en tres modos:

MODE_FREE

Conversacion 100% libre. La IA genera respuestas segun el CharacterIdentity sin restricciones de grafo.

Ideal para: Charla casual, exploracion

MODE_SCRIPTED

Solo ejecuta nodos del grafo. Sin generacion de IA, todo el contenido esta pre-definido.

Ideal para: Cutscenes, tutoriales

MODE_HYBRID

Lo mejor de ambos mundos. El grafo controla la estructura, la IA genera el contenido.

Ideal para: Misiones, dialogos complejos

StartNode
Punto de entrada del grafo

Descripcion

El StartNode marca el punto de entrada unico del grafo de dialogo. Cada DialogueGraph debe tener exactamente un StartNode. Cuando se inicia un dialogo, la ejecucion comienza desde este nodo y continua al nodo conectado a su salida.

Opcionalmente, puede configurarse un trigger que permite iniciar este dialogo automaticamente cuando ocurre un evento especifico en el juego.

Conexiones

→
1 Salida

Parametros

Parametro Tipo Descripcion
triggeropcional String Nombre del evento que activa este dialogo automaticamente. Ejemplo: "talk_to_merchant"
■
EndNode
Termina la ejecucion del dialogo

Descripcion

El EndNode finaliza completamente la ejecucion del grafo de dialogo. No tiene salidas, ya que es un nodo terminal. Puede haber multiples EndNodes en un grafo para representar diferentes finales o caminos de salida.

El parametro reason es opcional y se usa para analytics o para distinguir entre diferentes tipos de finalizacion del dialogo.

Conexiones

1 Entrada

Parametros

Parametro Tipo Descripcion
reasonopcional String Etiqueta para identificar el tipo de finalizacion. Ejemplos: "good_ending", "bad_ending", "abort"
🧠
AIResponseNode
Genera respuestas dinamicas con IA

Descripcion

El AIResponseNode genera texto dinamicamente usando el LLM local (llama.cpp). Utiliza el CharacterIdentity configurado para mantener la personalidad del NPC, el WorldContext para informacion del mundo, y las memorias persistentes para continuidad narrativa.

Este nodo marca requires_inference: true en su resultado, indicando al GraphRunner que debe esperar la generacion de la IA antes de continuar.

StaticResponseNode
Texto pre-escrito fijo

Descripcion

El StaticResponseNode muestra texto pre-escrito sin generacion de IA. Es ideal para lineas de dialogo importantes que deben ser exactas, cutscenes, tutoriales, o cuando no se requiere variabilidad.

Soporta sustitucion simple de variables usando la sintaxis {variable_name}. Por ejemplo: "Hola {player_name}, bienvenido a {town_name}."

☰
PlayerChoiceNode
Presenta opciones al jugador

Descripcion

El PlayerChoiceNode presenta un conjunto de opciones al jugador y espera su seleccion. Cada opcion puede tener una condicion de visibilidad que determina si se muestra o no basandose en el estado del juego.

El nodo tiene una salida por cada opcion definida. Cuando el jugador selecciona una opcion, el flujo continua por la salida correspondiente (slot 0 para primera opcion, slot 1 para segunda, etc.).

Conexiones

←
1 Entrada
N
N Salidas (una por opcion)

Parametros

Parametro Tipo Descripcion
promptopcional String Pregunta o contexto mostrado antes de las opciones. Ejemplo: "Que deseas hacer?"
choicesrequerido Array[Dictionary] Array de opciones. Cada opcion tiene:
  • text: Texto visible de la opcion
  • condition: Expresion que controla visibilidad (opcional)
  • metadata: Datos adicionales (opcional)
Validacion: Requiere al menos 1 opcion en choices.

ConditionNode
Bifurcacion logica condicional

Descripcion

El ConditionNode evalua una condicion y bifurca el flujo del dialogo. Tiene dos salidas: TRUE (slot 0) y FALSE (slot 1). Soporta dos modos de operacion: comparacion simple (variable + operador + valor) o expresion GDScript completa.

Conexiones

←
1 Entrada
✓
TRUE (slot 0)
✗
FALSE (slot 1)

Parametros

Parametro Tipo Descripcion
variableopcional* String Nombre de la variable a comparar. Ejemplo: "player_gold", "quest_completed"
operatoropcional int (enum) Operador de comparacion:
== (EQUAL) != (NOT_EQUAL) > (GREATER) >= (GREATER_EQUAL) < (LESS) <= (LESS_EQUAL) contains is_empty is_true is_false
valueopcional Variant Valor contra el cual comparar. Puede ser int, float, String, bool, etc.
expressionopcional* String Expresion GDScript completa. Ejemplo: "gold >= 100 and level > 5"

* Usa modo simple (variable + operator + value) O expresion, no ambos.

Validacion: Requiere variable O expression no vacio.

EventNode
Emite eventos/signals al juego

Descripcion

El EventNode emite un evento custom que el juego puede escuchar. Es ideal para activar misiones, dar items al jugador, cambiar estados del mundo, reproducir animaciones, o cualquier otra accion que deba ocurrir durante el dialogo.

Los datos del evento pueden incluir variables con la sintaxis $variable_name que seran sustituidas con valores del contexto.

SetVariableNode
Modifica variables del contexto

Descripcion

El SetVariableNode modifica variables en el contexto del dialogo. Soporta 6 operaciones diferentes y maneja automaticamente la conversion de tipos cuando es necesario (por ejemplo, operaciones con int y float producen float).

Conexiones

←
1 Entrada
→
1 Salida

Parametros

Parametro Tipo Descripcion
variablerequerido String Nombre de la variable a modificar. Ejemplo: "player_gold", "quest_active"
operationopcional int (enum) Tipo de operacion a realizar:
Set (=) Add (+) Subtract (-) Multiply (*) Divide (/) Toggle (!)
Default: Set
valueopcional Variant Valor para la operacion. No se requiere para Toggle.

Comportamiento por Operacion

Operacion Comportamiento
Set Asigna el valor directamente
Add Suma numeros, concatena strings, append a arrays
Subtract Resta numeros
Multiply Multiplica numeros (0 si variable es null)
Divide Divide numeros (resultado siempre float, 0 si divisor es 0)
Toggle Invierte el valor booleano
Validacion: Requiere variable no vacio.

JumpNode
Salta a otro grafo o nodo

Descripcion

El JumpNode permite saltar a otro DialogueGraph completamente diferente, o a un nodo especifico dentro del mismo grafo. Es util para modularizar dialogos complejos, reutilizar fragmentos de conversacion, o crear estructuras de dialogo ramificadas.

No tiene salidas visuales ya que el flujo continua en el destino del salto.

target_node_idopcional String ID del nodo especifico al que saltar. Si esta vacio, salta al StartNode del grafo destino.
Validacion: Requiere target_graph_id no vacio.

JumpToFreeNode
Transicion a modo conversacion libre

Descripcion

El JumpToFreeNode es un concepto unico de OhMyDialogSystem. Permite transicionar de un dialogo scripted (basado en grafo) a una conversacion completamente libre con la IA, manteniendo el contexto del personaje y las memorias.

Puedes configurar condiciones para que el sistema detecte cuando el jugador quiere volver al dialogo estructurado: palabras clave, expresiones evaluables, limite de intercambios, o timeout.

Conexiones

←
1 Entrada
→
1 Salida (post-retorno)

Parametros

Parametro Tipo Descripcion
context_promptopcional String Contexto adicional para la IA durante la conversacion libre. Ejemplo: "El jugador esta preguntando sobre la mision del herrero"
return_keywordsopcional Array[String] Palabras clave que disparan el retorno al grafo. Ejemplo: ["acepto", "trabajo", "mision"]
return_conditionopcional String Expresion GDScript que dispara el retorno cuando es verdadera.
max_exchangesopcional int Numero maximo de intercambios antes de forzar retorno. 0 = ilimitado
timeout_secondsopcional float Segundos antes de forzar retorno automatico. 0 = sin timeout
↩
ReturnToGraphNode
Sale del modo libre y retorna

Descripcion

El ReturnToGraphNode es el complemento del JumpToFreeNode. Indica al sistema que debe salir del modo de conversacion libre y retornar a la ejecucion estructurada del grafo.

Si no se especifica un return_node_id, el flujo continua desde la salida del JumpToFreeNode que inicio el modo libre.
