Wiki / API Reference / LlamaInterface

LlamaInterface

GDExtension C++

Interfaz de bajo nivel para llama.cpp. Carga modelos GGUF y gestione su ciclo de vida.

Nota: Esta clase es parte del módulo GDExtension nativo. Requiere que el addon esté correctamente compilado para tu plataforma.

// Herencia

RefCounted → LlamaInterface

// Descripcion

LlamaInterface proporciona una API de bajo nivel para cargar modelos de lenguaje en formato GGUF usando la librería llama.cpp. Esta clase maneja la inicialización del backend, carga de modelos, gestión de memoria y contexto de inferencia.

Es la base sobre la cual se construyen los componentes de más alto nivel como AIService y DialogueManager.

Uso Recomendado

Para la mayoría de casos, usar AIService en lugar de instanciar LlamaInterface directamente:

# Forma recomendada - usar AIService singleton
var ai_service := AIService.get_singleton()
if ai_service and ai_service.is_model_loaded():
    # El modelo ya está disponible globalmente
    pass

# Forma directa (bajo nivel) - instanciar LlamaInterface
var llama := LlamaInterface.new()
llama.load_model("res://models/model.gguf")

AIService gestiona el ciclo de vida del modelo, integra con ModelManager para descarga de modelos, y proporciona señales para cambios de estado.

Descripciones de Metodos

load_model

Error load_model(path: String, params: Dictionary = {})

Carga un modelo GGUF desde la ruta especificada.

Parámetros
Parámetro Tipo Descripción
path String Ruta al archivo .gguf. Soporta res:// y user://
params Dictionary Parámetros opcionales de configuración
Claves aceptadas en params
Parámetro Tipo Descripción
n_gpu_layers int Capas a descargar en GPU. Por defecto 999 (todas las que entren)
n_ctx int Tamaño de la ventana de contexto, en tokens. Por defecto 512
n_batch int Tamaño de lote para el procesado del prompt
n_threads int Hilos de CPU para generación
n_threads_batch int Hilos de CPU para el procesado del prompt
use_mmap bool Mapear el archivo en memoria en vez de leerlo entero
use_mlock bool Forzar al sistema a mantener el modelo en RAM
vocab_only bool Cargar SOLO el vocabulario, sin los pesos. Ver "Tokenizar sin cargar el modelo"

unload_model

void unload_model()

Libera el modelo, el contexto y el sampler. No hace nada si no hay modelo cargado.

apply_chat_template

String apply_chat_template(messages: Array, add_generation_prompt: bool = true)

Aplica la plantilla del modelo a una lista de mensajes y devuelve el prompt final.

Parámetros
Parámetro Tipo Descripción
messages Array Array de Dictionary con las claves role y content. Los que no tengan ambas se descartan con un warning.
add_generation_prompt bool Añade el encabezado que le indica al modelo que empiece a responder 
var prompt := llama.apply_chat_template([
    {"role": "system", "content": "Sos un herrero gruñón."},
    {"role": "user", "content": "¿Cuánto cuesta la espada?"},
])

count_tokens

int count_tokens(text: String) const

Devuelve la cantidad exacta de tokens que ocupa el texto, según el vocabulario del modelo. Devuelve -1 si no hay modelo cargado.

Por qué importa

La regla de ~4 caracteres por token se rompe con tildes, ñ y emojis: en español subestima el costo real. Este método usa el tokenizador del propio modelo.

Tokenizar sin cargar el modelo

Contar tokens sólo necesita el vocabulario, no los pesos ni el contexto. Con vocab_only el modelo se abre sin leer un solo tensor y sin reservar KV cache: cuesta megabytes en vez de gigabytes.

var llama := LlamaInterface.new()
llama.load_model("res://models/qwen2.5-3b-instruct-q4_k_m.gguf", {
    "vocab_only": true,
    "n_gpu_layers": 0,
    "n_ctx": 512,
})

var tokens := llama.count_tokens("¿Cuántos tokens ocupa esta frase?")

El addon ya hace esto por vos: TokenCounter (core/token_counter.gd) cachea un handle por ruta de modelo y lo usa el editor para mostrar el costo real de cada nodo AI Response.

Un handle vocab_only sirve para tokenizar, NO para generar. Además deja n_ctx_train sin poblar, así que el tamaño de contexto del archivo no se puede leer por esta vía.

generate

String generate(prompt: String)

Genera la respuesta completa y la devuelve. Cadena vacía ante cualquier error.

Bloquea el hilo que la llama

Llamada desde el hilo principal, congela el juego hasta el último token. Para gameplay usá generate_async o generate_streaming.

generate_async

void generate_async(prompt: String)

Genera en el WorkerThreadPool y entrega el texto por generation_completed. No devuelve nada.

generate_streaming

void generate_streaming(prompt: String)

Igual que generate_async, pero además emite token_generated por cada token a medida que sale.

llama.token_generated.connect(func(token): label.text += token)
llama.generation_completed.connect(func(full): print(full))
llama.generate_streaming("Hola, ¿qué vendés?")

Ambas emiten generation_started al arrancar. Si ya hay una generación en curso, avisan por consola y no hacen nada. Sin modelo cargado emiten generation_error.

is_generating

bool is_generating() const

True mientras hay una generación async o streaming en curso. Es atómico: se puede consultar desde cualquier hilo.

get_generation_progress

float get_generation_progress() const

Progreso de 0.0 a 1.0, calculado como tokens emitidos sobre max_tokens. Devuelve 0.0 si no se está generando.

Es un progreso contra el techo, no contra la respuesta real: si el modelo termina antes de max_tokens, nunca llega a 1.0.

cancel_generation

void cancel_generation()

Pide abortar la generación en curso. No hace nada si no hay ninguna.

Espera a que el worker termine

Esta llamada bloquea hasta que la tarea se detiene de verdad. Es lo que garantiza que no queden hilos sueltos, pero significa que cancelar desde el hilo principal cuesta un frame corto.
