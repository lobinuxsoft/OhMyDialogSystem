Architecture

OhMyDialogSystem sigue una arquitectura en capas que separa claramente las responsabilidades entre el runtime nativo (C++), la logica de juego (GDScript), y las herramientas del editor.

Capas del Sistema

El addon se organiza en 5 capas principales, cada una con responsabilidades especificas:

🎨
Editor Layer

Herramientas visuales para crear y configurar dialogos. Solo se ejecuta en el editor de Godot.

model_manager_window.gd dialogue_graph_editor.gd *_inspector_plugin.gd nodes/*.gd
🤖
AI Layer

Gestion de modelos, descarga desde HuggingFace, y construccion de prompts.

prompt_builder.gd model_downloader.gd huggingface_api.gd gguf_parser.gd
🧠
Core Layer

Logica principal de dialogos. DialogueManager coordina GraphRunner y AIService.

dialogue_manager.gd ai_service.gd graph_runner.gd node_executors/*.gd
📦
Resources Layer

Datos serializables: grafos de dialogo, personajes, mundos, configuracion de modelos.

dialogue_graph.gd character_identity.gd world_context.gd model_config.gd
⚡
GDExtension Layer (C++)

Wrapper nativo de llama.cpp. Inferencia LLM con soporte GPU (Vulkan/CUDA/Metal).

llama_interface.h llama_interface.cpp thirdparty/llama.cpp

Componentes Principales

Flujo de Alto Nivel

La interaccion entre los componentes principales sigue este flujo:

DialogueManager
Coordina todo el sistema
GraphRunner
Ejecuta el grafo de nodos
AIService
Genera respuestas IA

AIService Singleton

AIService es un singleton global que proporciona acceso centralizado a la inferencia LLM:

Singleton Global AIService Gestiona el ciclo de vida de LlamaInterface.
Carga/descarga modelos en runtime. Disponible via AIService.get_singleton() 
# Acceso al singleton
var ai_service := AIService.get_singleton()

# Verificar si hay modelo cargado
if ai_service.is_model_loaded():
    var llama := ai_service.get_llama()
    llama.generate_async("Hello!", 100)

DialogueManager

DialogueManager es el punto de entrada para los desarrolladores. Coordina:

  • GraphRunner - Ejecuta grafos de dialogo nodo por nodo
  • AIService - Genera respuestas dinamicas via LLM
  • PromptBuilder - Construye prompts con contexto (personaje, mundo, historial)
  • Query System - Permite al juego influir en los dialogos
# Uso tipico de DialogueManager
var dialogue_manager := DialogueManager.new()
add_child(dialogue_manager)

# Configurar contexto
dialogue_manager.default_character = load("res://merchant.tres")
dialogue_manager.world_context = load("res://fantasy_world.tres")

# Iniciar dialogo
dialogue_manager.start_dialogue(dialogue_graph, DialogueManager.DialogueMode.HYBRID)

# Conectar senales
dialogue_manager.npc_speaking.connect(_on_npc_speaking)
dialogue_manager.player_choices_available.connect(_on_choices)

Ejecucion de Grafos

GraphRunner

GraphRunner interpreta los DialogueGraph ejecutando cada nodo en secuencia:

Patron Strategy: Cada tipo de nodo tiene un NodeExecutor dedicado que implementa su logica especifica.

Node Executors

StartNodeExecutor
Punto de entrada
EndNodeExecutor
Fin del dialogo
AIResponseExecutor
Respuesta LLM
StaticResponseExecutor
Texto fijo
PlayerChoiceExecutor
Opciones al jugador
ConditionExecutor
Bifurcacion logica
EventExecutor
Dispara eventos
SetVariableExecutor
Modifica variables
JumpToFreeExecutor
Entra modo libre
ReturnToGraphExecutor
Vuelve al grafo

Estados de Ejecucion

GraphRunner mantiene un estado interno que determina el comportamiento:

Estado Descripcion
IDLE Sin grafo activo
RUNNING Ejecutando nodos
WAITING_INPUT Esperando input del jugador (choice/text)
FREE_MODE Conversacion libre con IA
PAUSED Pausado manualmente
COMPLETED Grafo finalizado normalmente
ERROR Error durante ejecucion

Modos de Dialogo

OhMyDialogSystem soporta tres modos de dialogo, cada uno con diferentes niveles de control:

FREE

Conversacion 100% IA

  • Sin grafo predefinido
  • El jugador escribe libremente
  • IA genera todas las respuestas
  • Ideal para NPCs emergentes

SCRIPTED

Grafo tradicional

  • Sigue el grafo estrictamente
  • Respuestas predefinidas
  • Choices fijos
  • Maximo control narrativo

HYBRID

Lo mejor de ambos

  • Grafo como esqueleto
  • IA enriquece respuestas
  • JumpToFree para zonas libres
  • Balance control/dinamismo

Flujo de Datos

Generacion de Respuesta IA

Cuando un nodo AIResponse se ejecuta, el flujo es:

1GraphRunner ejecuta AIResponseNodeData
2DialogueManager recibe senal de inferencia requerida
3PromptBuilder construye prompt con: sistema, personaje, mundo, historial
4AIService obtiene LlamaInterface y llama generate_streaming()
5LlamaInterface (C++) ejecuta inferencia en llama.cpp
6Tokens emitidos via token_generated signal
7DialogueManager emite npc_speaking para actualizar UI

Editor vs Runtime

Separacion Critica: El codigo del editor NUNCA debe estar acoplado al codigo de runtime. Los builds exportados no incluyen el editor.

Tipo Ubicacion Se ejecuta en export?
Runtime core/, resources/, ai/ SI
Editor-only editor/ NO

Consideraciones

  • AutoLoad: AIServiceAutoload se registra automaticamente para runtime
  • Export Plugin: ModelExportPlugin copia los modelos GGUF al build
  • res:// es read-only en exports - los modelos van en user://
