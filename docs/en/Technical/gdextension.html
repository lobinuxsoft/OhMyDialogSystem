GDExtension Build Guide

Complete guide to compile the OhMyDialogSystem GDExtension with llama.cpp integration.

Prerequisites

All Platforms

  • Python 3.10+ with pip
  • SCons 4.x+: pip install scons
  • CMake 3.20+
  • Ninja (recommended for faster builds)
  • Git (for submodules)

Linux

Package Fedora/Bazzite Ubuntu/Debian
C++ Compiler gcc-c++ build-essential
Development Headers libstdc++-devel libstdc++-dev

Bazzite/Fedora Silverblue (rpm-ostree): If there are version conflicts with gcc, download the exact version from Koji.

Windows

  • Visual Studio 2022 with C++ workload, or
  • MinGW-w64 (GCC 12+)
  • CMake (from cmake.org or Visual Studio)
  • Vulkan SDK (for GPU acceleration): vulkan.lunarg.com

macOS

  • Xcode Command Line Tools: xcode-select --install
  • CMake: brew install cmake ninja

Compilation

1. Clone with submodules

git clone --recursive https://github.com/lobinuxsoft/OhMyDialogSystem.git
cd OhMyDialogSystem

If already cloned:

git submodule update --init --recursive

2. Compile llama.cpp (first time)

# Linux/macOS (Vulkan by default, fallback to CPU if not available)
./gdextension/scripts/build_llama.sh

# Windows (requires Vulkan SDK installed)
gdextension\scripts\build_llama.bat

# Force CPU only (no GPU acceleration)
./gdextension/scripts/build_llama.sh --cpu

3. Compile GDExtension

Using the build scripts (recommended)

The build.bat (Windows) and build.sh (Linux/macOS) scripts simplify the process:

cd gdextension

# Windows
build.bat editor          # For development in the editor
build.bat debug           # For exporting in debug mode
build.bat release         # For exporting in release mode

# Build all 3 configurations at once (Windows)
build_all.bat

# Linux/macOS
./build.sh editor
./build.sh debug
./build.sh release

Important: To open the project in the Godot editor, you must compile with editor. The template_debug target is only for exporting the game, not for development.

Understanding the targets

Target Usage When to compile
editor Development in the Godot editor Always - needed to open the project
template_debug Export game with debug enabled When you want to test exports with debugging
template_release Export optimized game for production For distributing the final game

Using SCons directly

If you prefer manual control:

cd gdextension

# Linux
scons platform=linux target=editor

# Windows
scons platform=windows target=editor

# macOS
scons platform=macos target=editor

Build Options

llama.cpp Options

Option Values Default Description
llama_backend vulkan, cpu, metal vulkan Compute backend (Vulkan recommended for GPU)
llama_native yes, no no Native CPU optimizations (not portable)
llama_avx2 yes, no yes AVX2 instructions (x86_64)
llama_rebuild yes, no no Force rebuild of llama.cpp

Example:

scons platform=linux target=template_release llama_backend=vulkan llama_native=yes

Standard godot-cpp Options

Option Values Description
platform linux, windows, macos, ios, android Target platform
target editor, template_debug, template_release Build type
arch x86_64, arm64 Target architecture

GPU Acceleration

Vulkan (Recommended)

Vulkan is the default GPU backend. It works on AMD, Intel and NVIDIA GPUs. Requires Vulkan SDK installed:

# Linux (Fedora)
sudo dnf install vulkan-devel shaderc

# Linux (Ubuntu/Debian)
sudo apt-get install libvulkan-dev glslc

# Windows: Download from https://vulkan.lunarg.com/

The build script automatically detects if Vulkan is available. If not, it falls back to CPU.

# Build with Vulkan (default)
./gdextension/scripts/build_llama.sh

# Or explicitly
./gdextension/scripts/build_llama.sh --vulkan

CUDA: Support for CUDA with GPU architecture selection is planned for a future version. See project issues for status.

Troubleshooting

"cannot find -lstdc++"

The build requires static libstdc++ by default. If not available, the SConstruct automatically uses dynamic linking. For distribution, consider:

# Fedora
sudo dnf install libstdc++-static

"llama.cpp not found"

Ensure the submodules are initialized:

git submodule update --init --recursive

CMake errors during llama.cpp build

The build scripts use these flags to avoid optional dependencies:

  • -DLLAMA_CURL=OFF - Disables model download (not needed)
  • -DLLAMA_BUILD_TOOLS=OFF - Skips CLI tools (not needed)

Output

The compiled libraries are placed in addons/ohmydialog/gdextension/:

📦 addons/ohmydialog/gdextension/
🪟 Windows
  • ⚙️ libohmydialog.windows.editor.x86_64.dll editor
  • ⚙️ libohmydialog.windows.template_debug.x86_64.dll debug
  • ⚙️ libohmydialog.windows.template_release.x86_64.dll release
🐧 Linux
  • ⚙️ libohmydialog.linux.editor.x86_64.so editor
  • ⚙️ libohmydialog.linux.template_debug.x86_64.so debug
  • ⚙️ libohmydialog.linux.template_release.x86_64.so release
🍎 macOS
  • 📁 libohmydialog.macos.editor.framework/ editor
  • 📁 libohmydialog.macos.template_debug.framework/ debug
  • 📁 libohmydialog.macos.template_release.framework/ release

Only the binaries for the platform and target you compile are generated. For a complete development setup, compile at least the editor target for your platform.
