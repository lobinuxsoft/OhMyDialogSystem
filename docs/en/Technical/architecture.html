Architecture

OhMyDialogSystem follows a layered architecture that clearly separates responsibilities between the native runtime (C++), the game logic (GDScript), and the editor tools.

System Layers

The addon is organized into 5 main layers, each with specific responsibilities:

🎨
Editor Layer

Visual tools for creating and configuring dialogues. Only runs in the Godot editor.

model_manager_window.gd dialogue_graph_editor.gd *_inspector_plugin.gd nodes/*.gd
🤖
AI Layer

Model management, download from HuggingFace, and prompt construction.

prompt_builder.gd model_downloader.gd huggingface_api.gd gguf_parser.gd
🧠
Core Layer

Main dialogue logic. DialogueManager coordinates GraphRunner and AIService.

dialogue_manager.gd ai_service.gd graph_runner.gd node_executors/*.gd
📦
Resources Layer

Serializable data: dialogue graphs, characters, worlds, model configuration.

dialogue_graph.gd character_identity.gd world_context.gd model_config.gd
⚡
GDExtension Layer (C++)

Native wrapper for llama.cpp. LLM inference with GPU support (Vulkan/CUDA/Metal).

llama_interface.h llama_interface.cpp thirdparty/llama.cpp

Core Components

High-Level Flow

The interaction between the main components follows this flow:

DialogueManager
Coordinates the entire system
GraphRunner
Executes the node graph
AIService
Generates AI responses

AIService Singleton

AIService is a global singleton that provides centralized access to LLM inference:

Global Singleton AIService Manages the LlamaInterface lifecycle.
Loads/unloads models at runtime. Available via AIService.get_singleton() 
# Access the singleton
var ai_service := AIService.get_singleton()

# Check if a model is loaded
if ai_service.is_model_loaded():
    var llama := ai_service.get_llama()
    llama.generate_async("Hello!", 100)

DialogueManager

DialogueManager is the entry point for developers. It coordinates:

  • GraphRunner - Executes dialogue graphs node by node
  • AIService - Generates dynamic responses via LLM
  • PromptBuilder - Builds prompts with context (character, world, history)
  • Query System - Allows the game to influence dialogues
# Typical usage of DialogueManager
var dialogue_manager := DialogueManager.new()
add_child(dialogue_manager)

# Configure context
dialogue_manager.default_character = load("res://merchant.tres")
dialogue_manager.world_context = load("res://fantasy_world.tres")

# Start dialogue
dialogue_manager.start_dialogue(dialogue_graph, DialogueManager.DialogueMode.HYBRID)

# Connect signals
dialogue_manager.npc_speaking.connect(_on_npc_speaking)
dialogue_manager.player_choices_available.connect(_on_choices)

Graph Execution

GraphRunner

GraphRunner interprets DialogueGraphs by executing each node in sequence:

Strategy Pattern: Each node type has a dedicated NodeExecutor that implements its specific logic.

Node Executors

StartNodeExecutor
Entry point
EndNodeExecutor
End of dialogue
AIResponseExecutor
LLM response
StaticResponseExecutor
Fixed text
PlayerChoiceExecutor
Player options
ConditionExecutor
Logic branching
EventExecutor
Fires events
SetVariableExecutor
Modifies variables
JumpToFreeExecutor
Enters free mode
ReturnToGraphExecutor
Returns to graph

Execution States

GraphRunner maintains an internal state that determines behavior:

State Description
IDLE No active graph
RUNNING Executing nodes
WAITING_INPUT Waiting for player input (choice/text)
FREE_MODE Free conversation with AI
PAUSED Manually paused
COMPLETED Graph finished normally
ERROR Error during execution

Dialogue Modes

OhMyDialogSystem supports three dialogue modes, each with different levels of control:

FREE

100% AI conversation

  • No predefined graph
  • Player writes freely
  • AI generates all responses
  • Ideal for emergent NPCs

SCRIPTED

Traditional graph

  • Strictly follows the graph
  • Predefined responses
  • Fixed choices
  • Maximum narrative control

HYBRID

Best of both worlds

  • Graph as skeleton
  • AI enriches responses
  • JumpToFree for free zones
  • Control/dynamism balance

Data Flow

AI Response Generation

When an AIResponse node is executed, the flow is:

1GraphRunner executes AIResponseNodeData
2DialogueManager receives inference required signal
3PromptBuilder constructs prompt with: system, character, world, history
4AIService gets LlamaInterface and calls generate_streaming()
5LlamaInterface (C++) runs inference in llama.cpp
6Tokens emitted via token_generated signal
7DialogueManager emits npc_speaking to update UI

Editor vs Runtime

Critical Separation: Editor code must NEVER be coupled with runtime code. Exported builds do not include the editor.

Type Location Runs in export?
Runtime core/, resources/, ai/ YES
Editor-only editor/ NO

Considerations

  • AutoLoad: AIServiceAutoload is automatically registered for runtime
  • Export Plugin: ModelExportPlugin copies GGUF models to the build
  • res:// is read-only in exports - models go in user://
